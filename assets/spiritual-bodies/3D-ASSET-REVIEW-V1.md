# 3D-ASSET-REVIEW-V1 · Code-Ready 资产入库规范

> 审核对象：从静态灵体图像到 **Claude + Three.js / WebGL 纯代码 3D 互动网页**的可追溯素材包。**图像美观不是唯一标准。**
> 版本：v1.0 (pilot), 2026-11-21。适用于 01–11 资产，不追认已生成参考图为真实正交视图。

## A. 图像及数据包评分：100 分

| ID | 关键指标 | 满分 | 测试 / 证据 | 拒绝条件 |
| --- | --- | ---: | --- | --- |
| FID | **原图忠实度** | 15 | 对照原图核对人体姿态、色彩走向、发光点数量和头顶光束 | 关键造型系统丢失 |
| MV | **多视角几何一致性** | 25 | 正/侧/背：肢体角度、关节、节点轴线及深度推断不冲突；标清正交或透视 | 视图互相矛盾且无解释 |
| GEO | **纯代码三维几何可重建性** | 20 | 基于 Mesh/Curves/Particles 可指定可重复参数；禁止平面贴图假三维 | 只能靠 2D 图片显示 |
| LAY | **图层/参数化完整度** | 15 | Body、Rainbow Curves、Nodes、Crown Beam、Post FX 拆分；有控制参数与文件映射 | 核心层混成不可分割位图 |
| SHD | **Shader/光效复现性** | 15 | 透明度、颜色梯度、动态流线和 Bloom 可用代码实现，有可解释的混合方式 | 光效依赖合成图无法重现 |
| INT | **动画/交互准备度** | 10 | 旋转/缩放、速度、颜色、亮度、层开关、时间参数及输入映射有说明 | 无交互对象或参数 |

**分数计算**：逐项独立整数评分，合计 100 分。每项必须写出 *Observed / Inferred / Unknown*，不把推断冒充观察。评分来自人工技术审阅，未运行代码之前不可宣称实测合格。

- **≥75**：可申请 **Stage A / Reference Approved**；还需要通过证据完整性硬门槛。
- **60–74**：**Stage A Candidate / Needs Evidence**，可以存入 review/draft 目录，不允许标为已批准。
- **<60**：先纠正关键视角与图层。
- **无论分数高低**：**只有 Stage B 的实际运行验收通过才能标记为 Code-Ready Approved**。

## B. 入库两道硬门槛

**Stage A · Reference Approved**
1. 保留可确认的原始上传文件，并有资产编号和来源关系。
2. 每张视图独立图片，不得以拼图替代独立图层；写明 FRONT/SIDE/BACK/THREE-QUARTER/TOP-OBLIQUE。
3. 原图/生成视图/代码推断/程序渲染四类必须分开标记，不得混用。
4. 实际上传文件可在 GitHub 中打开；必要时存储字节数与校验和。
5. 评分 ≥75，无未经说明的关键几何冲突。

**Stage B · Code-Ready Approved**
在实际浏览器中执行、留存截图或测试记录，以下全部通过才可放行：
1. WebGL Scene 中存在真实 **三维 Mesh / Curve / Shader**；关闭底图后 360° 旋转时仍可识别正、侧、背，不准用 billboard 伪造。
2. 固定同一母模型输出 Front/Side/Back/Top/45° 摄像机视图，关键身体轮廓和能量节点位置经人工与原图对比。
3. Body / RainbowFlow / Nodes / CrownBeam 可 **独立显示/隐藏**；材质、位置、颜色等参数能改变效果。
4. 交互：拖动旋转、滚轮缩放、光流播放/暂停和速度修改，均通过实机检查。
5. 在目标设备测试帧率、内存、渲染错误；记录实际环境，不预设合格性能数据。
6. 成品代码、资产清单、需求、差异记录和验证证据同仓可追踪。

## C. 数字约定

- **世界坐标**：x=左右，y=上，z=前；正面相机在 +z，右侧相机在 +x；以脚底为 y=-0.925m，顶部约 y=+0.925m，**1.85m 仅为建模归一化假设**，不是原画测量。
- **原图证据**优先；生成图里的新增细节属于 *inferred*。
- **Curve 规范**：每条流线独立 ID；给出颜色、3D 控制点、宽度/半径、是否依附人体、运动方向、透明度。
- **Node 规范**：独立 ID、颜色、中心点、半径、亮度；同轴只是初版假设。
- **Crown 规范**：锥形体积分布、若干环、动画、与头顶的相对高度。
- **可复刻范围**：同一套源代码渲染各视图，不能靠分别生成五张艺术图强行拼凑。
- **Code prototype 与 Approved asset 不等价**：只说明技术路径跑得通，不表示忠实度已验收。

## D. 项目模板

每个编号下推荐：
```text
XX-asset-name/
  source/                  # 原始上传，保留
  version-A/views/         # 生成参考图（尚未 3D 对齐）
  version-A/layers/        # 独立视觉/结构层参考
  review/README.md         # 6项评分+问题+依据
  review/asset-spec.json   # 3D 参数假设、曲线路径、节点
  prototype/index.html     # Three.js 最小交互打板
  prototype/README.md      # 运行方法、限制、验收记录
  version-B/               # 未来高精度升级，不能覆盖 A
```

## E. 实施顺序

原图固定 → 分层与空间假设 → 参数资产 JSON → Three.js 纯代码母模型 → 同一场景多相机 → 可交互层控制 → 实测审查 → 用户明确确认正式入库。

参考 Three.js 官方文档：[Three.js Docs](https://threejs.org/docs/)。本规范中的评分阈值是本项目制定的内部管理标准，不是行业认证。
